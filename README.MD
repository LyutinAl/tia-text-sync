# tia-text-sync

Инструмент для командной разработки проектов Siemens TIA Portal в Git.

TIA Portal хранит проект в бинарном виде: изменения в нём не видны в `git diff`, их нельзя обсудить на ревью, а правки нескольких человек трудно свести. `tia-text-sync` подключается к открытому проекту через TIA Openness и раскладывает программу ПЛК по текстовым файлам. Файлы повторяют дерево проекта, их можно сравнивать, ревьюить и загружать обратно в TIA Portal.

## Возможности

- **Экспорт** блоков, таблиц тегов, UDT и технологических объектов в папки, повторяющие группы проекта. SCL, STL и DB сохраняются исходниками, LAD и FBD сохраняются в XML с текстовым видом для чтения.
- **Сравнение** проекта с рабочей папкой по содержимому файлов. Отличия отмечаются в дереве проекта.
- **Импорт** изменённых или новых элементов из рабочей папки обратно в TIA Portal.
- **Архив проекта** `.zap21` для Git LFS, чтобы любую версию проекта можно было открыть целиком.
- Снимок аппаратной конфигурации `hw.xml`: только для отслеживания изменений, обратно не загружается.

## Требования

- Windows 10/11 x64
- TIA Portal V21, установленный в папку по умолчанию
- .NET Framework 4.8
- Пользователь Windows в группе **Siemens TIA Openness**. Группа создаётся при установке TIA Portal. После добавления нужно выйти из Windows и войти снова.
- Git, а для архива проекта ещё и [Git LFS](https://git-lfs.com/) (`git lfs install`)

## Сборка

Для сборки нужен [.NET SDK](https://dotnet.microsoft.com/download), проверено с версией 10. Эталонные сборки .NET Framework 4.8 он скачивает сам. TIA Portal на машине сборки не нужен, но нужны две сборки Openness. Они не хранятся в репозитории: скопируйте их с машины, где установлен TIA Portal V21.

```text
C:\Program Files\Siemens\Automation\Portal V21\PublicAPI\V21\net48\Siemens.Engineering.Base.dll
C:\Program Files\Siemens\Automation\Portal V21\PublicAPI\V21\net48\Siemens.Engineering.Step7.dll
```

Положите их в `libs\V21\net48\` и соберите проект:

```bash
dotnet build tia-text-sync.sln
```

Результат появится в `bin\Debug\net48\`. Для запуска достаточно скопировать `tia-text-sync.exe` и `tia-text-sync.exe.config` на машину с TIA Portal. Сборки Openness при запуске берутся из установки TIA Portal.

## Начало работы

1. Откройте проект в TIA Portal и запустите `tia-text-sync.exe`.
2. Выберите **TIA Portal → Подключиться к открытому в TIA**. При первом подключении новой версии программы TIA Portal спросит разрешение на доступ через Openness: разрешите его.
3. Нажмите **Рабочая папка...** и выберите корень Git-репозитория проекта. Папка запоминается между запусками.
4. Выберите устройство в дереве и выполните **Экспорт → Устройство целиком**. Закоммитьте результат.

## Работа в команде

**Отправить свои правки.** После работы в TIA Portal выполните **Сравнить → Весь проект**. Изменённые элементы отметятся в дереве. Затем **Экспорт → Отличия по последнему сравнению**, проверьте `git diff` и закоммитьте.

**Получить правки коллег.** После `git pull` выполните **Сравнить → Весь проект**. Элементы, которые отличаются в папке, и новые файлы коллег будут отмечены. Затем **Импорт → Отличия по последнему сравнению**. Перед загрузкой программа покажет, сколько элементов будет создано и перезаписано, а после загрузки сразу сравнит их с папкой.

Импорт перезаписывает элементы в TIA Portal. Перед ним выгрузите свои несохранённые в Git правки, иначе они будут потеряны.

Импорт ничего не удаляет из TIA Portal. Если файла нет в папке, это может значить, что коллега ещё не отправил его в Git, поэтому удалять такие элементы нужно вручную.

### Отметки в дереве

| Отметка | Значение |
| ------- | -------- |
| `• отличается` | Элемент в TIA и файл в папке различаются |
| `• нет в папке` | Элемент есть в TIA, файла нет |
| `• нет в TIA` | Файл есть в папке, элемента в TIA нет: удалён в TIA или добавлен через Git |
| `• не скомпилирован` | Элемент изменён и не скомпилирован, TIA Portal не выдаёт его содержимое |
| `• ошибка экспорта` | Элемент не удалось выгрузить, причина в логе |

Отметки показывают результат последнего сравнения. После правок в TIA Portal запустите сравнение снова.

### Кнопки

| Кнопка | Действие |
| ------ | -------- |
| **Сравнить** | Выбранное в дереве или весь проект |
| **Экспорт** | Выбранное в дереве, отличия по последнему сравнению, устройство целиком или архив проекта |
| **Импорт** | Выбранное в дереве, отличия по последнему сравнению или устройство целиком |
| **Инструменты** | Обновить дерево; компилировать ПЛК при экспорте, сравнении и импорте; сохранять архив проекта при каждом экспорте |

Выбранным может быть устройство, ПЛК, группа или отдельный элемент.

## Структура рабочей папки

```text
<рабочая папка>/
  <Проект>.zap21              архив проекта (Git LFS), если он сохраняется
  .gitattributes              правило Git LFS для архива, добавляется автоматически
  <Устройство>/
    hw.xml                    снимок аппаратной конфигурации
    <ПЛК>/
      blocks/<группы>/        блоки: .scl, .awl, .db, .xml и текстовый вид .lad / .fbd
      tags/<группы>/          таблицы тегов, .xml
      types/<группы>/         UDT, .udt
      tech/<группы>/          технологические объекты, .xml или .db
```

Папки групп повторяют дерево проекта TIA Portal. Системные блоки лежат в `blocks/System blocks/`.

## Ограничения

- Работает только с TIA Portal V21, установленным в папку по умолчанию.
- Не скомпилированные блоки TIA Portal не экспортирует. Скомпилируйте ПЛК или включите компиляцию в меню **Инструменты**, она изменяет состояние проекта.
- Защищённые know-how блоки SCL/STL пропускаются.
- Файлы `.lad` / `.fbd` нужны только для чтения: при импорте используется XML.
- Аппаратная конфигурация, системные блоки и технологические объекты, сохранённые как `.db`, обратно не загружаются.
- Архив проекта создаётся только из сохранённого проекта. Если в TIA Portal есть несохранённые изменения, программа предложит сохранить проект.
